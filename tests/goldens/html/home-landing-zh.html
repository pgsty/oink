常见问题

关于这一页，大家都会问

答案是块级 Markdown，列表与多个段落都能照常使用。

真的只有一个文件？

导航栏与页脚之间的部分是。导航来自 hugo.yaml，页脚来自 data/footer/zh.yaml，中间每一块都来自 data/home/zh.yaml。

每种语言都得有一个文件吗？

单语言站点用一个 data/home.yaml 就够。本站是双语，所以用 data/home/en.yaml 与 data/home/zh.yaml。

同一种区块可以出现多次吗？

可以，给每个条目不同的 key：

  • { type: gallery, key: products }
  • { type: gallery, key: case_studies }

本页那三面 Logo 墙，就是同一种区块读三份不同的数据。

没写 url 会怎样？

这一项按普通内容渲染——不留空链接，也不留坏链接。上面三张卡片里，有两张就没写 url。

自由 Markdown

逃生口

预定义的集合表达不了时，把 Markdown 直接写进数据文件。

这一段是同一个 YAML 文件里的一个 body: 字符串。它支持段落、链接与列表：

  • 不需要自定义模板；
  • 就是普通的 Goldmark 渲染；
  • 与上面每一块同样的宽度与竖向节奏。

设计原则

行为可预期

01

内容优先

多数改动只是数据文件里的纯文本。

02

默认无障碍

语义化区块、受控的外链，以及原生的 FAQ 折叠控件。

03

向后兼容

没有 sections 列表的首页数据，保持它一直以来的顺序。
