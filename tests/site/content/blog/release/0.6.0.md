0.5.0 froze the component API. 0.6.0 spends that stability on two things a
documentation theme still could not do well: present long-form blog writing
without inventing another content type, and survive an author's typo.

The first half is a reading release. Five independent options on the ordinary
blog shell remove the sidebar and breadcrumb, leave the outline alone in a
wider rail, and use the page's own image as a full-bleed backdrop. Around that
presentation the blog finally has
the pieces a blog needs: featured images on the post, authors with profiles,
  series with a reading order, card and table indexes beside the row index, and a share
bar that is sixteen plain links and no third-party script.

The second half is invisible until something is wrong. The theme used to
stop the build on any invalid input — 548 `errorf` calls across 116 files.
One typo in one page's front matter served HTTP 500 on every URL of a running
`hugo server`. All 548 are gone. A bad value now warns, says what it expected,
falls back to the documented default, and lets the build finish; the
publishing gates run `--panicOnWarning`, so it is still fatal exactly where
that matters.

Nothing in 0.5.0 was retired. A 0.5.0 site builds on 0.6.0 unchanged, with
two default values moved — see [Migration](#migration).

## At a glance {#at-a-glance}

- **Immersive reading without another type.** Five ordinary blog options remove
  the sidebar and breadcrumb, leave the outline alone in a wider rail, and use
  `featured_image: hero` for the opening. Everything below the fold is the same
  blog article.
- **The blog is finished.** Featured images on the post (`banner`, `wash`,
  `hero`), multiple authors with profiles and bylines, article series with a
  reading order and a position strip, card and table indexes beside the row index with
  an optional reader-side switch, and a page-end share bar.
- **Attribution for vendored pages.** `upstream_link` and its companions
  render one attribution line naming the work, its holder, its licence and
  where the full notice lives; `translation_notice` marks a page as a
  translation and links the authoritative version.
- **The build bends instead of breaking.** Zero `errorf` in the theme. Every
  invalid value warns with what it got, what was allowed, and what it used
  instead. `--panicOnWarning` keeps it fatal at the gates.
- **The outline knows where you are.** The rail's dot leads the accent line in
  the direction you are reading, and the heading you are standing in takes a
  pill and `aria-current="location"`.
- **Dates are ISO.** `time_format_blog` and `time_format_default` now default
  to `2006-01-02`, the one format every locale reads the same way.

## Immersive reading on the blog shell {#immersive-reading}

There is no `article` type and no second shell. A page or section cascade
combines five independent options on the ordinary blog shell:

- `sidebar_enabled: false` removes the sidebar slot;
- `breadcrumb: false` removes the breadcrumb while the navbar remains available;
- the right rail carries the outline alone, wider than the docs rail, sticky
  in flow so it travels with the opening and pins only after you scroll;
- `featured_image: hero` paints the shared page image behind the opening.

Because these are presentation options, bylines, tags, series, feeds, pager
order, and page-end composition remain on the existing blog path. Each option
can be changed independently for one page without creating a parallel layout.

The featured image gains a `hero` mode: the resolved image becomes a
full-bleed decorative backdrop across
the top of the viewport, masked out before the text starts, with the title
block moved down to make room. `navbar_enabled: true` on a hero page overlays
the navbar on a fading scrim that scrolls away with the image.

```yaml
# One blog section uses the immersive presentation.
cascade:
  featured_image: hero
  toc_style: flow
  toc_taxonomies: false
  sidebar_enabled: false
  breadcrumb: false
```

`hero` on any other type warns and renders as `wash`.

## The blog, finished {#blog}

### The featured image, on the post {#featured-image}

The theme has always resolved one image per page for list rows and social
cards, but never rendered it on the post — so authors wrote the hero by hand.
Across the eleven consuming sites, 559 articles opened with a literal
`[![featured](...)](...)` duplicating the `images` value the front matter
already carried.

`params.ui.featured_image` renders it instead:

| Mode | What it does |
| --- | --- |
| `none` | The default. Nothing is rendered. |
| `banner` | A framed 16:9 figure above the title, so a run of articles keeps one rhythm. |
| `wash` | The image behind the article header at a tenth of its opacity, masked out before the text. |
| `hero` | A full-bleed backdrop on the blog shell; warns and uses `wash` elsewhere. |

It draws from the same resolver as the social card, so the image at the top of
an article and the image its card carries cannot disagree. It adds no runtime,
no Page Store flag and no bundle member. Front matter `featured_image` turns
one page — or, in a cascade, one section — on or off.

### Authors {#authors}

`taxonomies: {author: authors}` is the entire switch; the theme adds no
parameter. An author's profile *is* the term page: `title` is the display
name, `description` the one-line bio, the body is the profile text, and
`images` is the portrait. A page with no portrait gets an initial in a circle
rather than a broken frame.

A post names them in front matter (`authors: [vonng, oink]`) and
gets a byline on the article and inside the metadata sentence on rows. A post
that still carries the 0.4 `author:` string keeps working and takes the
shorter sentence.

### Series {#series}

`taxonomies: {series: series}` is again the whole switch. The term page
`content/series/<name>/_index.md` is the introduction; members declare
`series: [<name>]` and `series_weight`. A series term page lists its members
in **reading order** rather than reverse date — that is the feature — and each
article carries a strip saying where the reader is and where to go next.

### The index, in three forms {#blog-index}

`params.ui.blog_index` chooses how a blog section's list page renders:

| Key | Default | Meaning |
| --- | --- | --- |
| `ui.blog_index` | `list` | `list` (rows), `cards` (a grid), or `table` (a compact archive). |
| `ui.blog_index_columns` | `3` | Card columns; two between md and xxl, one below md. |
| `ui.blog_index_size` | `12` | Posts per page. |
| `ui.blog_index_toggle` | `false` | Adds a locally remembered reader-side switch between all three forms. |

A site whose posts lead with an image had no way to show it at more than
250×125 px; a card gives it a 16:9 crop above the title. Card images go
through Hugo's `.Fill`, so a grid does not download a full-size original per
card. The table is a complete unpaginated archive unless the toggle is on; then
all three forms share one paginator slice. The toggle stays off by default
because it keeps every form in the document. Term and taxonomy pages keep rows.

One line of metadata now sits under every post title in a list, a card or a
term archive, and it is **one translated sentence** rather than fragments
joined in a template — because "in" is not a word every language puts between
the same two things, and a byline is not a suffix in every language either:

```text
English   2026-08-20, By OINK maintainers, In Releases
Chinese   2026-08-20，由 OINK 维护者 发布于 版本发布
```

### Sharing {#share}

`params.ui.share` is a list drawn from `x`, `bluesky`, `mastodon`, `facebook`,
`linkedin`, `reddit`, `hackernews`, `telegram`, `whatsapp`, `line`,
`pinterest`, `weibo`, `chatgpt`, `claude`, `email`, `copy`. Empty — the
default — means no bar.

Every entry is a plain link or the local copy button. No platform script, no
share count, no request until a reader activates one. Front matter
`share: [x, copy]` replaces the list for one page and `share: false` turns one
page's bar off; a section cascade scopes the bar to, say, the blog. Only a
regular page renders it.

`copy_link` also joins the action registry and the Command Palette, so the
canonical URL is one keystroke away from anywhere.

The page end is now ordered Share, Feedback, Annotation, Pager, Comments.

## Page annotation {#annotation}

A site that vendors third-party material had no way to say so. Two keys
shipped in 0.5 (`upstream_attribution`, `downstream_modified`) rendered a bare
link and nothing else.

0.6.0 replaces them with a model that renders one attribution line naming the
work, who holds it, the licence it carries, and where the full notice lives:

| Key | Where it resolves from |
| --- | --- |
| `upstream_link` | The page. The one per-page fact. |
| `upstream_name`, `upstream_copyright`, `upstream_license`, `upstream_notice`, `upstream_ref`, `upstream_modified` | Site params, the `data/upstreams` entry named by `upstream_source`, or the page — most specific last. |

`upstream_license` takes an SPDX identifier resolved through the new
`data/licenses` table. Because the constants normally arrive by cascade, a
page inside a vendored tree that carries no `upstream_link` warns and renders
no notice rather than publishing an unattributed copy; `upstream_link: ""` is
the deliberate opt-out. An incomplete attribution, an unknown SPDX identifier
or a non-boolean `upstream_modified` behave the same way: a partial notice
reads exactly like a complete one, so the theme renders none.

`params.ui.translation_notice` takes the language code of the authoritative
version. A page in another language that has a translation there says so and
links it; `translation_notice: false` opts out a page written natively in this
language.

The theme now mounts `data/`, which it did not before, so the licence table
reaches a consuming site without being copied into it.

## A build that warns instead of stopping {#warn-not-stop}

This is the one change that alters how your CI behaves.

At v0.5.0 the theme called `errorf` in **548 places across 116 files**. Every
one of them aborted the whole build. In `hugo server` that meant one author's
typo in one page's front matter served HTTP 500 on every URL of the site, not
just the page being edited.

All 548 are gone. The theme calls `errorf` nowhere. Instead:

- an invalid value **warns** with the value it got, the range it allowed and
  the fallback it used, then returns that fallback;
- `layouts/_partials/validate.html` is the one place a value is checked, in
  four shapes (`enum`, `bool`, `length`, `number`), so the messages are
  consistent and a site-wide typo is reported once rather than per page;
- a render hook degrades the block, not the site: an unsafe CSS length falls
  back to the default, a diagram without its server URL renders nothing, a
  malformed download record is dropped;
- **`--panicOnWarning` is what makes it fatal.** Every gate that publishes
  anything already builds with it: the theme's CI, `bin/sites/build-all.py`,
  and the site repository's own pages workflow.

The protection was never the halting. It was refusing to emit bad output —
and that is unchanged. What changed is that a preview no longer goes down
with it.

Two consequences worth stating plainly:

- **If your CI does not pass `--panicOnWarning`, add it.** Otherwise a build
  that used to fail now succeeds with a degraded page.
- **The renamed-key registries are gone.** 0.5.0 shipped two partials that
  failed the build on a renamed 0.4 key and named the replacement. Every
  consuming site is migrated, so they were pure carrying cost. A renamed key
  is now simply an unknown key — run
  `bin/migrations/oink06.py check --site <dir>` if you are unsure.

## The outline rail {#outline}

The right-rail outline now carries two states over one SVG path.

The **range** is every heading currently on screen: the accent is clipped to
it, and the dot parks on whichever end you are travelling towards — the bottom
while moving down the page, the top after a reversal of more than 24px — and
transitions faster than the clip, so the accent reads as being dragged along
behind the dot rather than leading it.

The **cursor** is the one heading you are standing in. It takes
`aria-current="location"` and a pill, and it is folded into the range so it
can never be lit outside the accent. It uses the same rule as `j`/`k`: the
last heading whose top has crossed the root scroller's *computed*
`scroll-padding-top`, so a jump always lands on the entry it lights.

## Fixed {#fixed}

- **Mounted content no longer leaks an absolute build path.** A page whose
  content is mounted from outside Hugo's working directory — the normal shape
  for a Hugo Modules site — had its full filesystem path baked into the edit,
  history and new-page links, four times per page including the JSON action
  manifest. The links 404'd, and the build machine's directory structure
  (usually including a username) was published to every visitor. Those actions
  now resolve or are simply not offered.
- **A generic attribute value can no longer close its own attribute.** Eleven
  render hooks wrote `data-*` and `aria-*` values with Go's `%q`, which
  escapes a double quote with a backslash that HTML does not recognise. A
  value carrying a quote came out as broken markup, and an `on*` handler could
  be smuggled past the policy that had just refused `on*`. All twelve emitters
  now share one escaping partial.
- **The language switch no longer leaves the site.** Its links were absolute
  URLs built from the configured `baseURL`, so a preview or a staging host
  jumped to production on every switch.
- **Field anchors a reader can derive.** Every `fields` entry had an anchor,
  but it was positional; it is now derived from the entry name, and each field
  description renders in its own scope so ids inside one cannot collide with
  another.
- **A wordmark no longer hides the brand mark.** A site that set
  `params.wordmark` rendered the wordmark *instead of* its logo in the navbar
  and the sidebar.
- **Book numbering and print.** Numbered objects list in document order rather
  than by a source position that never matched; footnote ids are namespaced in
  whole-Book print, so chapters carrying references no longer emit colliding
  `fn:1`; a numbered example frames its body as one unit; heading ids are
  namespaced in every print aggregate rather than only Book.
- **A project issue needs only the project repository.** The action was nested
  with the page-derived links, so a docs site whose code lives elsewhere lost
  the one action it had configured.
- **The outline dot no longer detaches** from the accent line under fast
  scrolling.

## Configuration {#configuration}

Everything below is additive except the two date formats.

| Key | Default | Notes |
| --- | --- | --- |
| `ui.featured_image` | `none` | `none` \| `banner` \| `wash` \| `hero` |
| `ui.blog_index` | `list` | `list` \| `cards` \| `table` |
| `ui.blog_index_columns` | `3` | Card columns |
| `ui.blog_index_size` | `12` | Posts per page |
| `ui.blog_index_toggle` | `false` | Reader-side switch between all three forms |
| `ui.share` | `[]` | List of share targets; empty means no bar |
| `ui.translation_notice` | `false` | Language code of the authoritative version |
| `ui.toc_style` | `fixed` | `fixed` \| `flow` |
| `ui.toc_taxonomies` | `true` | Term clouds in the right rail |
| `time_format_blog` | `2006-01-02` | **Changed** from `Monday, January 02, 2006` |
| `time_format_default` | `2006-01-02` | **Changed** from `January 2, 2006` |

Front matter gains `featured_image`, `share`, `authors`, `series`,
`series_weight`, `blog_index`, `translation_notice`, and the `upstream_*`
family; each is the site key without `ui.`, as always.

Two taxonomies are conventions rather than parameters: declare
`taxonomies: {author: authors}` and `taxonomies: {series: series}` and the
features appear.

## Migration {#migration}

A 0.5.0 site builds on 0.6.0 unchanged. Three things are worth a look:

1. **Dates.** If you want localised prose dates back, set them explicitly:

   ```yaml
   params:
     time_format_blog: Monday, January 02, 2006
     time_format_default: January 2, 2006
   ```

2. **`--panicOnWarning`.** Confirm your build command passes it. Without it, a
   configuration mistake that used to fail the build now produces a warning
   and a degraded page.

3. **Early 0.6 drafts.** If a preview used `type: article`, return it to
   `type: blog` and apply the five independent immersive options above. The
   released theme has no `layouts/article/` compatibility path.

If you are coming from 0.4, nothing has changed about that path: run
`bin/migrations/oink06.py report --sites <dir>`, then `migrate --write`, then
`check`. The one difference is that a missed key no longer fails the build, so
run `check` rather than relying on the build to find it.

Sites vendoring third-party pages should also rename `upstream_attribution` to
`upstream_link` and `downstream_modified` to `upstream_modified`, and add the
companion keys — the old names warn and render no notice.

## Verification {#verification}

0.6.0 ships with the full checker suite green:

- source-level contracts — translation-key parity across 32 locales, the
  naming namespace, parameter shapes, typography-token boundaries, the vendored
  dependency inventory;
- output contracts — HTML structure, duplicate ids, the bundle graph, and an
  output trust check that fails on any inline event handler, `javascript:` URL
  or unexpected third-party host;
- four-state goldens over the maintained surfaces — interactive HTML, print HTML, plain
  Markdown, RSS and `llms.txt` — byte-compared;
- the browser runtimes under `node --test`, and the migration toolkit under
  `unittest`;
- the example site built warning-free with `--printPathWarnings
  --panicOnWarning`, on Hugo Extended 0.160.1 (the floor) and 0.164.0.
