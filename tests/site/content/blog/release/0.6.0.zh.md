0.5.0 冻结了组件 API。0.6.0 把这份稳定性花在了文档主题仍然做不好的两件事上：
不发明新内容类型也能呈现适合长文阅读的博客，以及在作者打错一个字时活下来。

前半是一个“阅读”版本。普通博客壳上的五个独立开关可以移除侧栏与面包屑，
让大纲独占一条更宽的轨道，并用页面自己的图作全幅背景。围绕这种呈现，
博客终于有了博客该有的部件：文章上的题图、带主页的作者、带阅读顺序的系列、
与行式索引并列的卡片和表格索引，以及一条由十六个纯链接组成、不含任何第三方脚本的分享条。

后半在一切正常时是看不见的。主题过去在任何非法输入上都会中止构建 —— 116 个文件里
548 处 `errorf`。一处 front matter 的笔误，会让运行中的 `hugo server` 在**每一个**
URL 上都返回 HTTP 500，而不只是正在编辑的那一页。这 548 处全部消失了。坏值现在会
警告、说明它期望什么、回退到有文档的默认值，并让构建走完；发布关卡都跑
`--panicOnWarning`，所以在真正要紧的地方它依然是致命的。

0.5.0 没有任何东西被退役。一个 0.5.0 站点在 0.6.0 上原样构建，只有两个默认值移动了
—— 见[迁移](#migration)。

## 概览 {#at-a-glance}

- **不增加类型的沉浸式阅读。** 五个普通博客开关移除侧栏与面包屑，
  让大纲独占一条更宽的轨道，并用 `featured_image: hero` 铺出开场。
  折叠线以下仍是同一篇博客文章。
- **博客补完了。** 文章上的题图（`banner`、`wash`、`hero`）、带主页与署名的多作者、
  带阅读顺序与位置条带的文章系列、与行式索引并列的卡片和表格索引（可选读者侧切换），
  以及一条页尾分享条。
- **引入页面的署名。** `upstream_link` 及其配套键渲染一行署名，点明作品、持有者、
  许可证以及完整声明所在；`translation_notice` 标记一页是译文并链接权威版本。
- **构建会弯，不会断。** 主题内 `errorf` 归零。每个非法取值都会警告，说明它收到什么、
  允许什么、改用了什么。`--panicOnWarning` 让它在关卡上依然致命。
- **大纲知道你在哪。** 轨道上的圆点朝你阅读的方向领先于高亮线，你所在的那个标题
  会获得一个胶囊底色和 `aria-current="location"`。
- **日期改为 ISO。** `time_format_blog` 与 `time_format_default` 现在默认为
  `2006-01-02` —— 所有语言读法一致的唯一格式。

## 博客壳上的沉浸式阅读 {#immersive-reading}

OINK 没有 `article` 类型，也没有第二套壳。单页或栏目 cascade 可以在普通博客壳上
组合五个彼此独立的开关：

- `sidebar_enabled: false` 移除侧栏槽位；
- `breadcrumb: false` 移除面包屑，导航栏仍然可用；
- 右轨只承载大纲，比 docs 轨道更宽，在流中吸附，随开篇一起移动，
  只有当读者向下滚动后才钉住；
- `featured_image: hero` 把共享的页面图片铺在开场背后。

这些只是呈现选项，因此署名、标签、系列、订阅源、翻页顺序和页尾仍走原有博客路径。
每个开关都能为单页独立调整，不需要维护一套平行布局。

题图相应新增 `hero` 模式：解析出的图片成为视口顶部的全幅装饰性
背景，在正文开始前被遮罩掉，标题块下移让出空间。hero 页面上设 `navbar_enabled: true`
会把导航栏叠在一层渐隐的对比蒙版上，并随图片一起滚走。

```yaml
# 一个博客栏目采用沉浸式呈现。
cascade:
  featured_image: hero
  toc_style: flow
  toc_taxonomies: false
  sidebar_enabled: false
  breadcrumb: false
```

在其他类型上使用 `hero` 会警告并按 `wash` 渲染。

## 博客补完 {#blog}

### 文章上的题图 {#featured-image}

主题一直会为每页解析一张图片供列表行与社交卡片使用，却从不在文章上渲染它 ——
于是作者手写开篇大图。在十一个消费站点里，有 559 篇文章以一行字面的
`[![featured](...)](...)` 开头，重复着 front matter 里已有的 `images` 值。

`params.ui.featured_image` 接管了这件事：

| 模式 | 作用 |
| --- | --- |
| `none` | 默认值，什么都不渲染。 |
| `banner` | 标题上方一个带框的 16:9 图形，让一串文章保持同一种节奏。 |
| `wash` | 图片以十分之一不透明度铺在文章头部背后，在正文开始前被遮罩掉。 |
| `hero` | 博客壳的全幅背景；用在其他类型上会警告并回退为 `wash`。 |

它与社交卡片走同一个解析器，所以文章顶部的图与卡片上的图不可能对不上。它不增加任何
运行时、任何 Page Store 标记、任何 bundle 成员。front matter 的 `featured_image`
可以为一页 —— 或通过 cascade 为一个栏目 —— 打开或关闭。

### 作者 {#authors}

`taxonomies: {author: authors}` 就是全部开关，主题不增加任何参数。作者主页**就是**
term 页：`title` 是显示名，`description` 是一句话简介，正文是主页文本，`images` 是头像。
没有头像的页面会得到一个圆形首字母，而不是一个破图框。

文章在 front matter 里点名（`authors: [vonng, oink]`），在正文页得到署名，
在列表行的元信息句子里也有一份。仍然携带 0.4 那种 `author:` 字符串的文章照常工作，
并使用较短的那句。

### 系列 {#series}

`taxonomies: {series: series}` 同样是全部开关。term 页
`content/series/<name>/_index.md` 是引言；成员声明 `series: [<name>]` 与
`series_weight`。系列 term 页按**阅读顺序**而不是倒序日期列出成员 —— 这正是这个功能的
意义 —— 每篇文章上方带一条条带，说明读者在哪里、下一篇是什么。

### 三种索引形态 {#blog-index}

`params.ui.blog_index` 决定一个博客栏目的列表页怎么渲染：

| 键 | 默认值 | 含义 |
| --- | --- | --- |
| `ui.blog_index` | `list` | `list`（行式）、`cards`（卡片网格）或 `table`（紧凑归档）。 |
| `ui.blog_index_columns` | `3` | 卡片列数；md 到 xxl 之间两列，md 以下一列。 |
| `ui.blog_index_size` | `12` | 每页文章数。 |
| `ui.blog_index_toggle` | `false` | 增加一个在三种形态间切换、并在本地记忆的读者控件。 |

一个文章以图片开篇的站点，此前没有办法把这张图显示得比 250×125 px 更大；卡片在标题
上方给它一个 16:9 裁切。卡片图片走 Hugo 的 `.Fill`，所以一屏网格不会为每张卡片下载
一份原图。单独使用表格时，它是一份不分页的完整归档；打开切换后，三种形态共享同一页数据。
切换默认关闭，因为它会把三种形态都留在文档里。term 页与分类页保持行式。

列表、卡片与 term 归档里，每个标题下现在都有一行元信息，而且它是**一整句翻译**，
不是模板里拼起来的碎片 —— 因为"in"不是每种语言都放在同样两样东西之间的词，
署名也不是每种语言里的后缀：

```text
English   2026-08-20, By OINK maintainers, In Releases
Chinese   2026-08-20，由 OINK 维护者 发布于 版本发布
```

### 分享 {#share}

`params.ui.share` 是一个列表，取值来自 `x`、`bluesky`、`mastodon`、`facebook`、
`linkedin`、`reddit`、`hackernews`、`telegram`、`whatsapp`、`line`、`pinterest`、
`weibo`、`chatgpt`、`claude`、`email`、`copy`。空值（默认）表示不渲染分享条。

每一项都是一个纯链接，或者那个本地复制按钮。没有平台脚本，没有分享计数，读者不点就没有
任何请求。front matter 的 `share: [x, copy]` 为一页替换整个列表，`share: false`
关掉某一页的分享条；栏目 cascade 可以把分享条限定在比如博客范围内。只有常规页面渲染它。

`copy_link` 同时加入了动作注册表与命令面板，规范 URL 在任何地方都只差一次按键。

页尾顺序现在是：分享、反馈、页面标注、翻页器、评论。

## 页面标注 {#annotation}

引入了第三方材料的站点此前没有办法说明这件事。0.5 里的两个键
（`upstream_attribution`、`downstream_modified`）只渲染一个光秃秃的链接。

0.6.0 用一个模型取代它们，渲染一行署名，点明作品、谁持有它、它携带的许可证，
以及完整声明在哪里：

| 键 | 解析来源 |
| --- | --- |
| `upstream_link` | 页面。唯一的每页事实。 |
| `upstream_name`、`upstream_copyright`、`upstream_license`、`upstream_notice`、`upstream_ref`、`upstream_modified` | 站点参数、`upstream_source` 指向的 `data/upstreams` 条目，或页面 —— 越具体越靠后。 |

`upstream_license` 接受 SPDX 标识符，通过新增的 `data/licenses` 表解析。由于这些常量
通常经由 cascade 到达，一个位于引入目录树内、却没有 `upstream_link` 的页面会警告并
不渲染任何声明，而不是发布一份无署名的副本；`upstream_link: ""` 是刻意的退出方式。
不完整的署名、未知的 SPDX 标识符、非布尔的 `upstream_modified` 都同样处理：一份残缺的
声明看起来和完整的一模一样，所以主题一个字都不渲染。

`params.ui.translation_notice` 接受权威版本的语言代码。另一种语言的页面若在那里有译文，
就会说明并链接过去；`translation_notice: false` 让本语言原生撰写的页面退出。

主题现在挂载 `data/`（此前不挂载），所以许可证表不必被复制进消费站点就能用上。

## 会警告而不是停下的构建 {#warn-not-stop}

这是唯一会改变你 CI 行为的变更。

在 v0.5.0，主题在 **116 个文件的 548 处**调用 `errorf`，每一处都会中止整个构建。
在 `hugo server` 下，这意味着某一页 front matter 里的一个笔误，会让站点的**每一个** URL
都返回 HTTP 500，而不只是正在编辑的那一页。

这 548 处全部消失。主题不在任何地方调用 `errorf`。取而代之的是：

- 非法取值会**警告**，说明它收到的值、允许的范围、以及使用的回退值，然后返回该回退值；
- `layouts/_partials/validate.html` 是唯一校验取值的地方，支持四种形态
  （`enum`、`bool`、`length`、`number`），因此消息措辞一致，站点级的笔误只报一次
  而不是每页一次；
- 渲染钩子降级的是那个块，不是整个站点：不安全的 CSS 长度回退到默认值，
  没有服务器 URL 的图表什么都不渲染，格式错误的下载记录被丢弃；
- **`--panicOnWarning` 才是让它致命的开关。** 每一个会发布东西的关卡本来就带着它：
  主题的 CI、`bin/sites/build-all.py`，以及站点仓库自己的 pages 工作流。

保护从来不来自"停下"，而来自"拒绝产出错误的输出" —— 这一点没有变。变的是预览不再
跟着一起倒下。

两个需要明说的后果：

- **如果你的 CI 没有传 `--panicOnWarning`，请加上。** 否则一个原本会失败的构建，
  现在会带着一个降级的页面成功。
- **改名键的注册表已经删除。** 0.5.0 曾经带两个 partial，会在遇到 0.4 旧键时让构建失败
  并给出替代写法。所有消费站点都已迁移，它们只剩下承载成本。改名后的旧键现在只是一个
  未知键 —— 不确定的话跑 `bin/migrations/oink06.py check --site <dir>`。

## 大纲轨道 {#outline}

右轨的大纲现在用一条 SVG 路径承载两种状态。

**范围**是当前在屏幕上的全部标题：高亮被裁剪到这个范围，圆点停在你正在前进的那一端 ——
向下阅读时是底端，反向超过 24px 后是顶端 —— 并且它的过渡比裁剪更快，所以视觉上是高亮
被圆点拖着走，而不是圆点跟着高亮。

**光标**是你正站在其中的那一个标题。它获得 `aria-current="location"` 与一个胶囊底色，
并且被折进范围之内，所以它不可能被点亮在高亮之外。它使用与 `j`/`k` 相同的规则：
最后一个顶边越过根滚动容器**计算后**的 `scroll-padding-top` 的标题，
因此跳转总会落在它点亮的那一条上。

## 修复 {#fixed}

- **挂载内容不再泄漏绝对构建路径。** 内容挂载自 Hugo 工作目录之外的页面 ——
  Hugo Modules 站点的常规形态 —— 会把完整的文件系统路径烤进编辑、历史与新建页面链接，
  每页四处，包括那份 JSON 动作清单。这些链接会 404，而构建机的目录结构
  （通常含用户名）被发布给了每一位访客。现在这些动作要么正确解析，要么干脆不提供。
- **generic 属性取值不再能闭合它自己的属性。** 十一个渲染钩子用 Go 的 `%q` 写出
  `data-*` 与 `aria-*` 取值，而 `%q` 用 HTML 不认识的反斜杠转义双引号。带引号的取值
  会产出损坏的标记，而一个 `on*` 处理器可以就此绕过刚刚拒绝了 `on*` 的策略。
  十二个发射点现在共用同一个转义 partial。
- **语言切换不再跳出站点。** 它的链接是用配置的 `baseURL` 拼出的绝对 URL，
  于是预览环境或预发布主机上每切换一次语言就跳到生产环境。
- **读者能推导出来的字段锚点。** 每个 `fields` 条目本来就有锚点，但它是位置式的；
  现在由条目名派生，并且每个字段描述在自己的作用域中渲染，一个字段内部的 id 不会与
  另一个碰撞。
- **wordmark 不再顶掉品牌标记。** 设置了 `params.wordmark` 的站点，在导航栏与侧栏里
  渲染的是 wordmark **而不是**它的 logo。
- **Book 的编号与打印。** 编号对象按文档顺序列出，而不是按一个从未匹配上的源位置；
  整书打印时脚注 id 带上命名空间，带引用的章节不再产出互相冲突的 `fn:1`；
  编号示例把标题与正文框成一个整体；heading id 的命名空间扩展到每一种打印聚合，
  而不只是 Book。
- **项目 issue 只需要项目仓库。** 这个动作此前与页面派生的链接嵌在一起，
  于是代码在别处的文档站点丢掉了它唯一配置过的动作。
- **大纲圆点在快速滚动时不再与高亮线脱开。**

## 配置 {#configuration}

除两个日期格式外，以下全部是新增。

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `ui.featured_image` | `none` | `none` \| `banner` \| `wash` \| `hero` |
| `ui.blog_index` | `list` | `list` \| `cards` \| `table` |
| `ui.blog_index_columns` | `3` | 卡片列数 |
| `ui.blog_index_size` | `12` | 每页文章数 |
| `ui.blog_index_toggle` | `false` | 三种形态之间的读者侧切换 |
| `ui.share` | `[]` | 分享目标列表；空表示不渲染分享条 |
| `ui.translation_notice` | `false` | 权威版本的语言代码 |
| `ui.toc_style` | `fixed` | `fixed` \| `flow` |
| `ui.toc_taxonomies` | `true` | 是否在右轨显示术语云 |
| `time_format_blog` | `2006-01-02` | **变更**，原为 `Monday, January 02, 2006` |
| `time_format_default` | `2006-01-02` | **变更**，原为 `January 2, 2006` |

front matter 新增 `featured_image`、`share`、`authors`、`series`、`series_weight`、
`blog_index`、`translation_notice`，以及 `upstream_*` 系列；一如既往，
每一个都是去掉 `ui.` 前缀的站点键。

两个 taxonomy 是约定而不是参数：声明 `taxonomies: {author: authors}` 与
`taxonomies: {series: series}`，功能就会出现。

## 迁移 {#migration}

一个 0.5.0 站点在 0.6.0 上原样构建。有三件事值得看一眼：

1. **日期。** 想要回本地化的散文式日期，显式设置即可：

   ```yaml
   params:
     time_format_blog: 2006年1月2日
     time_format_default: 2006年1月2日
   ```

2. **`--panicOnWarning`。** 确认你的构建命令带着它。没有它，一个原本会让构建失败的
   配置错误，现在只会产生一条警告和一个降级的页面。

3. **早期 0.6 草案。** 如果预览版本用过 `type: article`，请改回 `type: blog`，
   再按上文设置五个独立的沉浸式开关。正式版本不保留 `layouts/article/` 兼容路径。

如果你是从 0.4 过来的，那条路径没有任何变化：跑
`bin/migrations/oink06.py report --sites <dir>`，然后 `migrate --write`，然后 `check`。
唯一的区别是漏掉的键不再让构建失败，所以请跑 `check`，而不要指望构建替你发现。

引入第三方页面的站点还应把 `upstream_attribution` 改名为 `upstream_link`、
`downstream_modified` 改名为 `upstream_modified`，并补上配套键 —— 旧名会警告并
不渲染任何声明。

## 验证 {#verification}

0.6.0 的完整检查套件全部通过：

- 源码级契约 —— 32 个语言文件的翻译键对齐、命名空间、参数形态、
  字体 token 边界、vendored 依赖清单；
- 输出契约 —— HTML 结构、重复 id、bundle 图，以及一项输出信任检查：
  任何内联事件处理器、`javascript:` URL 或意外的第三方主机都会让它失败；
